# 4. CTPN  Connectionist Text Proposal Network

---

In this video, we will discuss the theory behind the CTPN algorithm.

CTPN stands for Connectionist Text Proposal Network.

This is one of the few text detection algorithms that allows end-to-end training and optimization.

This works reliably on multi-scale and multi-language texts.

On ICDAR 2013, this achieves an F score of .88 while on, ICDAR 2015, the F score was around point

six one, surpassing most of the state of the art methods present at that time.

And this runs around five to six frames per second, which was quite fast at that time.

Now let's discuss the text detection pipeline used in the CTPN algorithm.

The input image is first fed to a CTPN network that outputs the fine scale text proposals as shown by these red

boxes.

Then these text proposals are connected by using some algorithm that outputs the final detected text

boxes as shown by the green color.

So this is how simple its pipeline is.

So let's now discuss the main components in this pipeline, that is the CTPN algorithm,

What are these fine-scale text proposals and the text line formation algorithm?

So let's just let's first discuss the CTPN architecture.

The architecture of the connectionist text proposal network is shown in this figure.

But before discussing this architecture, let's first discuss the motivation behind choosing this architecture.

During 2015-16, lots of advancement was being made in the field of object detection.

Since the text detection problem seems almost similar to the object detection problem, the authors

of the CTPN paper thought of testing the state of the art object detection model directly on the text detection

problem.

The state of the art method present at that time was faster R-CNN, where the region proposal network first

generated the possible regions where objects can be present.

We call these regions as object proposals.

These proposals are then fed to a CNN detection model for further classification and refinement.

Thus, with the help of Region Proposal Network, the task is just reduced to predicting on these proposals

instead of the entire image.

Since for text, we have two cases, either there is text or no text, so the authors remove the expensive

CNN detection step and trained only the region proposal network

for text detection. But the results that they obtained was not satisfactory and was clearly lacking

accurate localisation.

So as you can see from this image that the text detection by region proposal network is difficult to accurately

predict the horizontal sides of the word's.

One of the reasons for this can be the spacing between the characters, thus making it confused to find

the start and end locations of a word.

To solve this problem, the authors thought of dividing the text line into a sequence of fine scale text

proposals as shown in this image where each proposal will have a fixed width of 16 pixels and represent

a small part of a text line.

And that's obvious to assume as a text line is just a sequence. So now by fixing the horizontal

location,

The task is now reduced to just predicting the vertical location of each text proposal.

To predict the vertical locations, one of the methods is to use a sliding window based approach where

we slide multi-scale windows to detect objects of different sizes.

But that approach is computationally expensive, so the authors adopted the anchor regression approach

from the faster R-CNN paper, where by using a number of anchors, we are able to predict objects in

a wide range of scale and aspect ratio.

So they designed 10 vertical anchors whose heights are varied from 11 to 283 pixels with a fixed

width of 16 pixels.

Now let's discuss how the CTPN is able to detect multi-scale text using these anchors.

So first, the input image is fed to a pre-trained VGG16 network from which we take out the last convolutional

layer that is conv5. Then we densely slide a three by three window through this convolutional feature

map.

This three by three window is then used as an input to a 256-dimensional Bi-LSTM that includes two 128

dimensional LSTMs.

The LSTM internal state is then mapped to a five hundred twelve dimensional, fully connected layer,

followed by an output layer that predicts the scores, vertical coordinates and the side refinements

of k anchors corresponding to each window location.

So this is the CTPN architecture.

Obviously, there might be some questions coming to your mind, such as why do we densely slide a three

by three window through this feature map and not the input image?

Second, why do we use by Bi-LSTM here?

And third, what are these labels in the output layer?

So let's try to answer these questions so as to get a better idea about the CTPN architecture.

For this, let's first understand what is effective stride and receptive field?

So effective stride means how much we move in the input image if we move by one pixel in the feature map.

for example, for the VGG16 conv5 layer, the effective stride is 16 pixels.

So this means that moving by one pixel in the conv5 feature map is equivalent to moving by 16 pixels

in the input image. The effective stride can be calculated from the pooling layers used in the network.

The receptive field represents the region in the input image that a particular feature map is looking

at.

For example, for the VGG16 conv5 layer, the receptive field for a three by three window is 228

by 228 pixels as shown in this image.

So densely sliding, a three by three window through a conv5 layer is equivalent to sliding a 228 by 228

window by 16 pixels in the input image.

The only difference is in terms of the computation that has to be done.

For a three by three window, we have three by three by c numbers to process, while for the same

in the input image, we have to process 228 by 228 by three numbers.

Thus because of the strong representational power of the CNN features, we have saved a lot of computation.

So that's why we prefer a sliding window through the feature map and not through the input image.

So I hope that you understood the sliding window concept.

Now let's understand why to use Bi-LSTM. Since text is a sequence and we already know that LSTMs are

great in encoding the sequential context information, so thus using LSTM will further boost the CTPN in making

more reliable prediction.

Further, using Bi-LSTM helps us to encode this contextual information in both directions.

And also now the receptive field is able to cover the whole image width.

So that's why they used Bi-LSTM.

Clearly, as can be seen from this image, that using Bi-LSTM helps in reducing false detections and at

the same time recovers the missed text proposals.

So that's why Bi-LSTM is used.

So now let's discuss how we have obtained these 2k, 2k and k output levels corresponding to each

window location.

Since we already know that the three by three window in the conv5 feature map corresponds to a 228 by

228 region in the input image.

Therefore, first, we will generate k anchors centered at the center of this 228 by 228 window

as shown here by the blue color.

In the CTPN paper, they have used 10 anchors with heights ranging from 11 to 283 pixels with the constant

width of 16 pixels.

Thus, corresponding to each anchor, we will get two scores that tells us the text and the non text

score associated with that anchor, 2 vertical coordinates that tells us how much to shift the height

and the center of that anchor and one side refinement that will be useful when we will merge the text

proposals.

So in this way, for each three by three window location, we will get 2k scores, 2k vertical coordinates

and k side refinements.

Once we obtain the output levels corresponding to each window position, the next task is to do some

post-processing in order to obtain the final text proposals or anchor boxes.

For this, we will first remove the anchor boxes whose text, non-text score is less than 0.7

Then we will apply non-max suppression to obtain the final text proposals.

Once we obtain the final text proposals, the next task is to merge these proposals in order to form

the final text boxes. For this, we will be using the text line formation algorithm.

In this algorithm, we first define paired neighbors, so 2 anchor boxes are called paired neighbors

when their horizontal distance is less than 50 pixels and their vertical overlap is greater than

0.7

So once all the paired neighbors are defined, we then sequentially connect all these paired neighbors to form

the final text boxes.

So this is how the CTPN algorithm is able to detect the text present in an image.

Now let's discuss about the training process.

That is how the training data looks like.

The training data consist of images and the corresponding text files as shown by this image.

The text file contains the eight bounding box coordinates in the clockwise order.

Sometimes they may also contain language and the associated text along with these eight coordinates.

From this training data, we need to generate the output levels in order to train the CTPN model.

So let's discuss how these training labels are generated from the training data.

For this first, the ground truth boxes are divided into fine-scale text proposals of 16 pixels width

as shown by this image.

Then to obtain the text/non-text score, we find the intersection over union of each anchor with the

ground truth box. if the IOU is greater than 0.7, we call it as the positive anchor.

If the IOU is less than 0.3, that anchor is called as the negative anchor.

Clearly, as can be seen from this image, these anchors shown here in blue color are all negative anchors.

Similarly, we calculate the scores for each anchor position.

So that's how we obtained these 2k scores.

Now let's discuss how to calculate these 2k vertical coordinates.

So for each of the positive anchor box, the vertical coordinates are given by this formula, where

cy*

is the y-axis center of the ground truth box.

cya is the Y-axis center of the anchor box, ha denotes the height of the anchor box and h-star represents

the height of the ground truth box.

These vertical coordinates, vc* and vh* are relative to the anchor boxes.

Therefore, these two vertical coordinates are not absolute, but are relative to the anchor boxes.

Similarly,

The side refinement is given by this formula, where wa represents the width of the anchor box, cxa

represents the X coordinate of the center of the anchor box and x-side star represents the x-axis side

coordinate of the ground truth box.

So once all the training labels are generated, the next task is to define the loss function. For CTPN,

the losses defined as the summation of the classification loss for scores and the regression loss for

both coordinates and the side refinements.

In the paper, they have used cross-entropy for the classification loss and Smoot-L1 for the regression

loss.

Here, lambda 1 and lambda 2 are the weightage given to both these losses in the paper, they have used

lambda 1 equal to one and LAMDA two equals to 2.

These Ns, Nv, and No are all normalization parameters denoting the number of anchors used by these

three losses.

The classification loss is calculated for all the anchors in the batch, while the regression loss for

coordinates is only calculated for the positive anchors, and the last one is calculated only for those

anchors that are within a horizontal distance of less than 32 pixels from the ground truth box.

So after setting all the other parameters, the network is trained end to end using stochastic gradient

descent.
