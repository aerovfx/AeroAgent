Now, this pre-trained model accepts the image in a certain format, so we need to prepare the input

image in order to make it compatible with the model.

Now, to prepare the image, we need to do certain things. First this model accept 4D blob as

input with order batch size, number of channels followed by height and weight.

But as you know, the input image is in height, width, and number of channels order.

So we need to convert this order to this.

Second, this model accepts images in RGB format, but as you know, that OpenCV reads in BGR format.

So we need to convert BGR to RGB.

Third, by training this model, all the images were normalized by subtracting the mean.

So while testing, we also need to subtract this mean from the input image.

Fourth, this EAST model only accepts images that have size a multiple of 32. If the size is not

a multiple of 32, then we will not be able to concatenate the feature maps together.

So let's take an example to understand this.

I hope you remember this architecture from the EAST video.

Suppose the input image size is (56, 56) which is not a multiple of 32.

So the size of these four feature maps will be 14, 7,3 and 1, as these are the outputs

of the second, third, fourth and fifth pooling

layers.

So their size will be one fourth, one eighth one 16 and one by 32 of the original size.

Now, when we will unpool them, then the size will be 2, 4, and 8.

So clearly, as you can see, we can't concatenate them as the size is different.

So you cannot concatenate 2 with 3, 4 with 7, and 8 with 14.

So this is the problem.

I hope you understood this.

Now, if the size is a multiple of 32, then no such problem arises this you can check yourself.

That's why the size should be a multiple of 32.

I hope you understood this.

So these are the four changes that you need to do in order to make the input image compatible with the

model.

Now, at first glance, this might look like a tedious task, but thanks to OpenCV that provides a

built-in function cv2.dnn.blobFromImage that does all these four things for us.

This takes as input the image that we want to prepare, the scale factor, the size that we want the

output image to be resized to, which should be a multiple of 32, the mean that we want to subtract

swapRB whether we want to swap the red and blue channels and the last parameter, whether we want

to crop the input image of not.

This function returns the prepared image is output.

The next argument is the size.

So once we have obtained the scope and geometry maps, we then need to do post-processing to obtain

the final text boxes.

So if you remember from the EAST video in post-processing, first the geometry map is converted back to

the bounding boxes, then we apply thresholding based on the score map to remove some low confidence

boxes.

And finally, the remaining boxes are merged using non-max suppression.

So let's first understand how to convert the geometric map to the bounding boxes.

Because this is a beginner-level course, so we will just be considering the horizontal text case. We will

consider the rotated text in the next course.

Now, if you remember, the five channels of the geometry map contains four distances and one angle.

The first channel denotes the distance from the top edge, the second channel denotes the distance

from the right edge, the third from the bottom edge and the fourth from the left edge of the bounding

box.

Now, to construct the bonding box from these four distances, we need to know the coordinates of the

top left and the bottom right vertices.

Let's denote them as top_x, top_y and bottom_x

bottom_y. And let's say the pixel location is (x,y).

So to construct the bounding box, we need to know these coordinates.

Now let's see how to find them.

So bottom X coordinate can be obtained by adding this distance as denoted by second channel to the pixel

location x.

So bottom X equals X plus second channel.

And bottom_y equals y plus third channel.

Similarly, top_x equals X minus fourth channel and top_y equals y minus first channel.

So this is easy to compute.

Once we have obtained these four values, we can easily construct the rectangle.

Now, if you remember, the output size of the geometry and  score map is one-fourth the size of the input

image.

This can also be verified by printing the shapes of input image, geometry, and score map.

Because of this, we need to multiply each pixel coordinate by four while calculating the bounding

box coordinates.

I hope you understood this.

Now let's implement this.

So here I have also attached the image with formulas so that it will be helpful for us.

So let's first create 2 lists for storing the rectangles and the confidence score.

Now, let's iterate over each pixel, row by row for constructing the bounding boxes.

So if the score of that pixel is less than some threshold, say, 0.1, we don't consider that

pixel for the bounding box generation.

So we simply continue.

Otherwise, we obtain the bounding box coordinates denoted by bottom_x, bottom_y, top_x, top_y

as we already discussed.

Finally, we append these to the rectangles and the confidence score list.

So this completes the first two steps in post-processing.

The last thing remaining is to apply the non-max suppression on these bounding boxes.

So here we will use the built-in non-max suppression function from the imutils.object detection package.

So one thing to remember is that this function only works for horizontal text boxes, so let's first
